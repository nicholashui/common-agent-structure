## What to write (when implementation is approved)

### Destination (per agent)

```text
agents/<agent_id>/evals/fixtures/
  provenance.json          # source paths + mapping
  chat-tc1.json
  chat-tc2.json
  chat-tc3.json
  run-tc1.json             # optional characterization of sealed execute
evals/regression/
  .gitkeep                 # keep; do not claim confirmatory
evals/benchmarks.json      # list fixture ids with honesty CHARACTERIZATION (not a pass)
```

Do **not** put cases in `tests/` as one file per agent (would explode the host suite). Host pytest **scans** fixtures.

Do **not** write `evals/reports/` as PASS. Reports stay empty / `NOT_RUN` until instruments are qualified.

### Fixture shape (proposed `casops.testcase.v1`)

```json
{
  "schema_version": "casops.testcase.v1",
  "id": "chat-tc1",
  "agent_id": "video.director",
  "path": "chat",
  "honesty": "CHARACTERIZATION",
  "input": {
    "message": "Define shot language and camera moves for a neon night market walk-and-talk",
    "history": []
  },
  "expect": {
    "http_status": 200,
    "agent_id": "video.director",
    "memory_writes": [],
    "plugins_executed": false,
    "t3_enabled": false,
    "network_granted": false,
    "io_declared_named": true,
    "io_declared_fetched": false,
    "truncated": false,
    "path_id": "chat"
  },
  "source": {
    "repo": "common-agent-swarm-ops",
    "file": "testcases/api_test/video.director/cases.json",
    "case_id": "tc1"
  }
}
```

`path: chat` uses CASOPS `POST /api/v3/agents/{id}/runtime/chat` with `message` = swarm-ops `goal` or `text`/`query`.  
`path: run` uses `POST .../runtime/run` / `Runtime.execute` — **no operator message**; expect sealed local adapter JSON with matching `agent_id` when `DEFAULT_LLM=local_deterministic`.

### Honesty (non-negotiable)

- Fixtures are **CHARACTERIZATION** / policy checks, not an eval **pass**.
- Do not copy swarm-ops `required_keys_any: ok, phases, v3, run_id` onto v3 Chat JSON.
- Do not copy v1 specials keys (`primary_intent`, `correlation_id`) unless CASOPS Chat actually returns them (it does not).
- Do not enable production, T3, network, plugins, or memory writes to make cases “richer.”
- Do not dump CoT. Do not invent `va_category`.
- Live xAI Chat is **not** a pytest golden. CI uses `local_deterministic` or mocked `post`. Operator may run Chat fixtures by hand against host LLM; results stay INDICATIVE.
- `casops-eval` remains `NOT_RUN` until instruments are QUALIFIED. Listing fixtures in `benchmarks.json` does not change that.

### Generator (when approved)

`tools/import_agent_testcases.py`:

1. Scan `agents/*/agent_spec.json`.
2. For each id, find swarm-ops `testcases/api_test/<mapped_id>/cases.json`.
3. Extract 3 human-language prompts (`goal` / `text` / `query`).
4. Write `chat-tc1..3.json` + `provenance.json`.
5. Write `run-tc1.json` for every agent: execute with local deterministic; expect `agent_id`, `memory_writes []`, `containment_stop null`.
6. Update `evals/benchmarks.json` to list those fixture ids with `"honesty": "CHARACTERIZATION"`.
7. Skip missing maps with a written skip list under `evals/fixtures/provenance.json` (`source: none`, still emit 3 Chat goals from `SPEC.md` first responsibility sentence or role string already on disk).

Idempotent: overwrite only `evals/fixtures/chat-*.json`, `run-tc1.json`, `provenance.json`, and the `benchmarks` array. Do not rewrite `analysis_plan.json` or `baselines.json`.
