## 2. Why this role exists

Human video crews already solve this problem under time pressure: Simulates audience preference, engagement, and drop-off. The agent form exists so the multi-agent system can **encode that craft continuously**, apply it on every handoff, and escalate only the residual risk to humans.

Its knowledge base is distilled from: **Pairwise preference datasets; retention studies; audience segmentation models** — historical design sources, not live network calls on this host.

The design ambition (surpass-human signal) is: *Predicts audience reaction earlier than conventional test-screen cycles.* Use that as the north-star metric when you write evals or proposals later.

## 5. When to involve this agent

- **Call this agent when** the work product needs a decision or artifact owned by *AudienceSimAgent*: Simulates audience preference, engagement, and drop-off
- **Pipeline phase:** Workflow support & release gates. Support functions and final release gates (accessibility, brand, legal, archive, etc.).
- **Do not call it for** generic orchestration, budget greenlight, or final legal sign-off unless those duties are explicitly in its responsibility — use producer/legal/compliance peers instead.
- **Human override:** any release-blocking safety, rights, or accessibility dispute escalates to a human gate even if the agent would auto-pass in a future active runtime.
